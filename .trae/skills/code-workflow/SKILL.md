# 代码开发工作流

## 概述

本技能提供从需求分析到代码提交的完整开发流程，每一步都会询问用户是否继续执行。

## 工作流步骤

### 阶段1：需求分析

1. **确认需求** ⚠️需要确认
   - 询问用户详细需求
   - 分析需求可行性
   - 确认技术方案
   - 等待用户确认后进入下一步

2. **创建任务列表** ⚠️需要确认
   - 使用 TodoWrite 创建开发任务
   - 明确每个任务的优先级
   - 等待用户确认后进入下一步

### 阶段2：代码开发

3. **代码实现** ⚠️需要确认
   - 根据需求编写代码
   - 遵循项目代码风格规范
   - 等待用户确认后进入下一步

4. **更新版本信息** ⚠️需要确认
   - 询问是否更新 changelog.txt
   - 询问是否更新 version.txt（版本号递增）
   - 记录本次修改内容
   - 等待用户确认后进入下一步

5. **代码检查** ⚠️需要确认
   - 运行 lint 检查
   - 执行类型检查
   - 代码格式化
   - 等待用户确认后进入下一步

6. **更新项目文档** ⚠️需要确认
   - 检查是否需要更新 project_structure.md
   - 更新 README.md（如有必要）
   - 同步文档与代码变更
   - 等待用户确认后进入下一步

### 阶段3：测试验证

7. **运行测试** ⚠️需要确认
   - 执行单元测试
   - 验证功能正确性
   - 等待用户确认后进入下一步

8. **功能测试** ⚠️需要确认
   - 手动测试核心功能
   - 记录测试结果
   - 等待用户确认后进入下一步

### 阶段4：打包构建

9. **打包构建** ⚠️需要确认
   - 检查前置条件：
     - Python 环境已安装
     - pyinstaller 已安装：`pip install pyinstaller`
   - 检查项目必要文件：
     - `main.py` - 程序入口
     - `static/version.txt` - 版本号文件
     - `static/favicon_256x256.ico` - 应用图标
   - 执行打包命令：`py build.py`
   - 验证打包结果：检查 `dist/` 目录下是否生成 `WAF工具_{版本号}.exe`
   - 等待用户确认后进入下一步

   **打包参数说明**：
   | 参数 | 说明 |
   |------|------|
   | `--onefile` | 打包为单个可执行文件 |
   | `--windowed` | 无控制台窗口（GUI 应用） |
   | `--icon` | 指定应用图标 |
   | `--add-data=static;static` | 包含静态资源目录 |

### 阶段5：代码提交

10. **代码审查** ⚠️需要确认
    - 检查修改内容
    - 确认代码质量
    - 等待用户确认后进入下一步

11. **提交代码** ⚠️需要确认
    - 显示待提交的文件列表
    - 询问用户确认提交（Y/N）
    - 添加修改文件
    - 编写提交信息
    - 推送到远程仓库（GitHub 和 GitLab）

## 使用说明

⚠️ **每一步执行前都会询问用户确认**：
- "是否执行此步骤？(Y/N)"

用户可以选择：
- **Y** - 执行当前步骤（执行完成后会再次询问是否继续下一步）
- **N** - 跳过当前步骤（直接进入下一步）
- **Q** - 退出工作流（终止所有后续步骤）

**关键确认点**：
- 阶段转换时需要确认
- 代码提交前会显示文件列表并确认
- 打包构建前需要确认
- 任何可能影响代码仓库的操作前都会确认

## 示例

```
开始代码开发工作流...

[阶段1: 需求分析]
步骤1: 确认需求
是否执行此步骤？(Y/N) Y
请输入需求描述: ...

步骤2: 创建任务列表
是否执行此步骤？(Y/N) Y
...
```

## 注意事项

1. 请确保已安装必要的依赖
2. 确保有有效的 Git 远程仓库配置
3. 建议在执行前保存所有工作

## 快捷键

- `Y` / `y` - 执行当前步骤
- `N` / `n` - 跳过当前步骤
- `Q` / `q` - 退出工作流
